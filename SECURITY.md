# Security Policy

## Supported Versions

The following table defines the active maintenance windows for HIKARU core modules.

| Version | Supported | Notes |
| ------- | :-------: | ----- |
| 5.1.x   | ✅        | Current Stable Release (Luminous Core) |
| 5.0.x   | ❌        | End of Life (EOL) |
| 4.0.x   | ✅        | Long-Term Support (LTS) - Identity Baseline |
| < 4.0   | ❌        | Legacy - No longer receiving security audits |

## Reporting a Vulnerability

HIKARU prioritizes the integrity of organizational intelligence. If you discover a potential security flaw or a breach of the Sanctuary Protocol, follow the escalation path below:

*   **Primary Contact:** Security vulnerabilities should be reported via the Guardian Core Secure Portal or by emailing security@hikaru-intelligence.enterprise.
*   **Encryption:** For highly sensitive disclosures, please use the PGP Key associated with the HIKARU Security Lead [Key ID: 0xHIKARU40].
*   **Response Timeline:**
    *   Acknowledgment: Within 12 hours of receipt.
    *   Initial Assessment: Within 48 hours.
    *   Status Updates: Every 72 hours until the vulnerability is remediated or mitigated.

## The Remediation Process

Upon receipt of a valid report, the HIKARU team will:

1.  **Triage:** Categorize the risk using CVSS v3.1 scores.
2.  **Isolation:** Implement temporary logic gates to prevent exploitation within the Integration Nexus.
3.  **Resolution:** Develop and test a patch.
4.  **Disclosure:** Once the patch is deployed to all OPERATORS, a coordinated disclosure will be published, crediting the researcher (unless anonymity is requested).

## Prohibited Actions

To maintain the Identity Preservation axiom, the following are strictly prohibited during research:

*   Accessing, modifying, or deleting data belonging to other OPERATORS.
*   Executing Denial of Service (DoS) attacks against the HIKARU infrastructure.
*   Social engineering of HIKARU administrative personnel.
